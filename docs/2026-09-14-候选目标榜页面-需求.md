# 候选跟单目标榜页面 需求

日期：2026-09-14
状态：待确认后实现

## 起因

go-follow 侧的 trader-scan 已跑出可用数据（run 3：24 小时窗口、随机抽样 2000 个地址、
按 `roi_closed` 排序）。现在只能用 curl 或裸接口看，不方便。要在本仓库加一个页面。

## 一处判断错误的更正（记下来避免重犯）

我先前在 go-follow 里塞了一个自带页面（`GET /trader-scan`，commit `a684cae`），
理由是「API 是 http，https 页面 fetch 会被混合内容拦；且生产没配 CORS」。

**那个理由不成立**：本仓库 `server/server.go` 自带反向代理（`/api/*` → go-follow，
去掉 `/api` 前缀），前端调的是相对路径 `/api/...`，**同源** —— 从来没有 CORS 或混合内容问题。
现有十几个 `/admin/*` 接口都是这么调的。

我没有先读前端怎么调 API 就下了结论。go-follow 里那个页面应当在本页面上线后删掉，
否则同一份榜有两个入口、两套代码。

## 数据来源

`GET /api/admin/trader-scan`（反代到 go-follow 的 `/admin/trader-scan`）。

**该接口无鉴权**（go-follow 侧按运维者要求去掉了）。但本页面放在 `RequireAuth` 内，
与其它页面一致 —— 登录后可见。两者不冲突：接口不挡，页面自己在登录后才渲染。

响应形状：
```
{ run: {...} | null, candidates: [...], limits: [string, ...] }
```

查询参数：`run`、`sort`（`roi_closed` 默认 / `realized`）、`min_hold_sec`、
`max_orphan_share`、`min_usdg_leg_share`、`min_closed_share`、`limit`（≤1000）、`offset`。
非法值一律 400（不静默回落）。

## 页面要有的东西

1. **run 溯源条**：run id、窗口（块区间 + 换算成小时）、判据（`min_txs`/`top_cap`）、
   `addrs_seen → addrs_delegated → addrs_analyzed` 三级漏斗、`git_rev`。
2. **`status` 横幅**：`partial` 时**必须显眼**并展示 `error` 全文。
   run 3 现在就是 `partial`（17 条曲线腿反查不出 ⇒ 账本可能有假信号），
   看榜的人必须先看到这句话。
3. **筛选控件**：对应上面的查询参数。
   **刻意不提供 `min_realized`** —— 它会扔掉小本金高 ROI 的地址，而那些人的成交规模
   与跟单者（`fixed 5 USDG`）相当、恰恰最该跟。实测：某地址赚 32.89 USDG 但 ROI 1.90、
   仓位平掉 94%、持仓 854 秒，比榜上「赚 7,570 但 ROI 0.98」的强一倍。
4. **「常用组合」一键填充**：`min_closed_share=0.5`、`max_orphan_share=0.3`、
   `min_usdg_leg_share=0.8`，排序留默认。
5. **表格列**：地址、`roi_closed`、`realized`、买/卖、币种数、`hold_min`、`hold_p50`、
   `reversal_min`、`orphan_share`、`closed_share`、`usdg_leg_share`。
   **`-1` 一律渲染成「—」而不是 -1** —— 那是「无法计算」，不是一个很小的数值。
6. **翻页**：`limit`/`offset`。单页上限 1000，而一次跑批可能 2000 行。
7. **地址操作**：一键复制。
8. **`limits` 九条**：默认折叠、可展开。第一条是覆盖范围自我声明
   （「只覆盖 7702 ∩ 活跃 ≥N 笔，不是高收益交易者榜」），那是 go-follow spec §4 的硬要求。

## 明确不做（本期）

- **不做「一键加为跟单目标」**。建目标要选钱包、设 `size_mode`/门槛/止盈止损，
  是另一个表单的事；而且榜是决策依据、建目标应当由人确认。留到需要时再说。
- 不做图表。列表 + 筛选已经够回答「跟谁」。
- 不做跨 run 对比视图。那要先有多次跑批，且「谁稳定盈利」是数据问题不是界面问题。
- 不做跑批触发按钮。一次跑批 100 分钟、打十万级 RPC、与生产共用同一台节点，
  不该由一次点击引发（go-follow spec §6 的原话）。

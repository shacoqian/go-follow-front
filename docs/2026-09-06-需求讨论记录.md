# go-follow-front 需求讨论记录

## 1. 背景（2026-09-06）

go-follow 的多用户后端（SQLite、SIWE 登录、钱包池、提现、导出/删除、并发评估）已合并到 go-follow master `00b657a`。前端作为独立产品开始设计。上游需求见 go-follow 仓库 `docs/2026-09-02-需求讨论记录.md` §11。

## 2. 结论

- **独立仓库**：`go-follow-front`（https://github.com/shacoqian/go-follow-front），本机 `/root/work/go-follow-front`，主分支 `main`。
- **托管方式**：不用 nginx。仓库自带一个 Go 小服务：`go:embed` 打包 `web/dist`，`/api/*` 反代到 gofollow，其余路径回 `index.html`；部署一个二进制 + `app.sh`。备选（Node / Bun / Caddy）已讨论，选 Go 是为了与 gofollow 部署方式一致、不引入运行时。
- **TLS**：第一版只做 HTTP，以后再接。
- **钱包**：只支持 OKX（`window.okxwallet`），不做 EIP-6963 通用发现和 WalletConnect。登录只用 `personal_sign`，提现由后端签名，前端不需要切链。
- **技术栈**：沿用 bridge-exchange 的 React 18 + Vite + TS + Tailwind + react-query + zustand + viem，加 shadcn/ui 与 react-hook-form/zod。界面是“一个应用壳 + 左侧导航，每个导航项一条路由”，代码按功能分片；ruoyi 式顶部多页签第一版不做。
- **页面范围**：第一版全做——登录、钱包池（创建/备注/禁用/导出密文/删除/提现）、目标地址、跟单任务向导与策略表单、仓位/手动卖出、决策与信号、管理员总览/用户/全站数据/审计/全局开关。
- **不做**：多页签、暗色主题、移动端、i18n、私钥导入。

## 4. 联调后的反馈（2026-09-06）

- **新建跟单改单页**：三步向导去掉。顶部“基本信息”卡片放目标下拉（+“新增目标”弹窗）与钱包下拉（+“创建钱包”弹窗，复用钱包页的创建对话框），选完一直可见并显示钱包余额；下面直接是策略表单，同页提交。编辑页同布局，目标与钱包只读。
- **买入策略字段**（后端同步改，见 go-follow `docs/superpowers/specs/2026-09-06-buy-sizing-target-filter-design.md`）：固定金额只有一个金额；按比例 = 比例（可 > 100%）+ 我方下限（可选）+ 我方上限（必填）；新增“目标买入过滤”分组：目标最小买入 / 目标最大买入，各自可选。
- 小数：界面最多 6 位小数，换算成最小单位整数提交；比例最多 2 位小数（bps 精度）。

## 5. 多账号切换（2026-09-06）

- **现状**：OKX 插件里切换账号，前端监听到地址变化即登出（防止用 A 的会话操作 B 的数据），回登录页后要手动再点登录；登录页不显示当前账号，页面里没有切换入口。
- **用户意见**：希望把“当前钱包连接的多个账号”做成下拉，在页面里直接切，不必回插件。用户在浏览器控制台验证 `eth_accounts` 返回了多个已授权地址（结论 1）。
- **结论**：
  - 登录页与顶部各放一个“账号”下拉，列出插件授权给本站的全部地址（`eth_accounts`），当前会话地址高亮；选中另一个地址即用该地址走一遍 SIWE 签名登录，成功后切换会话并清空查询缓存，失败（签名被拒或插件只允许当前选中账号签名）则提示“请在 OKX 里切到该账号后重试”并停留在原会话。
  - 登录页下拉在插件注入后自动读取并显示，`accountsChanged` 时同步刷新。
  - 切换保护改为：只有当会话地址不再出现在插件授权列表里（撤销授权、断开连接）才登出；插件里单纯切到另一个账号不再登出，因为页面顶部已明确显示当前会话账号（实现时发现：页内切到 B 后插件当前选中仍是 A，若沿用“选中≠会话即登出”，任何一次钱包事件都会把刚切好的会话踢掉）。登出后登录页预选插件当前地址，一次点击即可重登。
  - 下拉里可放“管理授权账号…”一项，调用 `wallet_requestPermissions` 弹插件的账号勾选框，用于新增授权地址；插件不支持该方法时隐藏此项。

真机结论（2026-09-06）：OKX 只返回当前选中账号，下拉仅一项；改为插件切换后自动弹签名登录，失败回登录页。

本机记住每个地址的会话（2026-09-06）：切到曾登录过的地址时，先复用本机保存的那个地址的会话（后端 TTL 168 h 内），用 `/auth/me` 校验通过即可，不用重新签名；校验不通过才签名登录。用户点登出清掉本机保存的全部地址的会话。

系统内切换已登录账号（2026-09-06）：系统内下拉列出本机记住的账号，可不经 OKX 直接切换（复用会话）；需要签名的操作要求 OKX 选中该账号，否则提示；插件事件只在选中账号真的变化时才自动切换（`pluginCurrent` 只归事件处理写，`useOkxAccounts` 的刷新只能在页面刚加载、还没有基准值时初始化一次，不然会抢在事件处理前面把变化提前"记账"，导致锁存事件补跑时被误判成没变而漏掉一次自动切换）。自动切换失败只清当前会话、忘记这次没切成功的目标地址，本机记住的其它账号原样保留——不像用户主动登出那样清空全部。

## 6. 第二轮页面意见（2026-09-07，待处理）

- **去掉“总额度”**：用户认为加仓次数已能约束每个代币的投入，总额度不需要。改法：前端策略表单去掉该字段，提交固定发 `spend_limit_usdg = "0"`；任务摘要不再显示；后端字段保留（0 = 不限），不改后端、不迁移。已提示：不同代币的数量没有上限，总投入实际只受钱包余额约束，用户接受。
- **删除“场所”“计价币”“跟内盘”这层过滤（前后端一起）**：用户明确“能解析到的信号全部跟”，这不是前端默认全选，而是系统里不再存在按场所/计价币挑选的概念；将来支持其它链也一样全跟。改法：后端删掉 `platformRule`、`quoteAssetRule`（计价币不支持的 `unsupported_quote` 仍保留，那是能力问题不是过滤）和 `follow_curve` 逻辑，任务表迁移删掉 `platforms`、`quote_assets`、`follow_curve` 三列，API 请求/响应不再有这三个字段，决策原因 `platform`、`quote_asset` 退役；前端表单与摘要删掉这三项。风险类过滤（创建者税上限、发射后跳过、黑名单、追价上限、目标买入过滤）保留。STOCK 计价信号追价口径偏高，追价上限提示里写一句建议放宽 0.5–1 个百分点。
- 后续多链：场所/计价币的可选集合应由后端按链给出（能力接口），前端不再硬编码；等确定要上的链再立项。
- **删除“创建者税上限”“发射后跳过”**（前后端一起，Pons 专属）：用户判断风险来自所选目标钱包本身，滑点与追价上限已兜底；实际运行发现问题再讨论。后端删 `creatorTaxRule`、`launchWindowRule`，任务表迁移删 `max_creator_tax_bps`、`skip_launch_window_sec`，决策原因 `creator_tax`、`launch_window` 退役。
- **黑名单改为按用户一份**：任务里去掉 `token_blacklist`，改成用户级黑名单（对该用户所有任务生效，只挡买入）。后端：新表或用户设置项存地址集合，`blacklistRule` 改读用户级；任务表迁移删 `token_blacklist`；新增 `GET/PUT /settings/blacklist`（本用户）。前端：钱包页或独立“设置”入口维护黑名单，任务表单不再出现。
- **数字输入拦负数**（2026-09-07，已做）：加仓次数、止盈/止损/持有超时/追价/滑点/重试的数字框加 `min`（加仓 1、滑点 0.01、其余 0）并在输入时拦掉 `-`/`+`/`e`；金额类文本框用小数键盘并拦负号。提交校验不变。
